# 入荷API v2 テストケースリスト

作成日: 2026-08-08

## テスト方針

既存 `/api/incoming/*` を変更しないことを最優先に確認する。

v2では、EOS対象の入荷予定をアプリが直接確定しないこと、予定なし入荷の重複作成を防ぐこと、オフライン再送で重複しないことを重点的に確認する。

## 前提データ分類

| 分類 | 内容 |
| --- | --- |
| EOS未確定 | JX送信済みで `PENDING` / `PARTIAL` の入荷予定 |
| EOS確定済み | EOS受信・適用済みで `CONFIRMED` の入荷予定 |
| 非EOS未確定 | FAX/手動/通常発注でEOS送信履歴がない未確定入荷予定 |
| 予定なし | 対応する入荷予定が存在しない入荷 |
| 仕入連携済み | `purchase_queue_id` 設定済み、または `TRANSMITTED` |
| 移動由来 | `order_source = TRANSFER` または transfer系カラムあり |

## スナップショット取得

| ID | ケース | 期待結果 | 確認観点 |
| --- | --- | --- | --- |
| S-001 | 倉庫ID指定でスナップショット取得 | 正常レスポンス | `warehouse`, `schedules`, `confirmed_eos_index`, `locations` が返る |
| S-002 | 未確定入荷予定がない倉庫 | 空配列で成功 | 404にしない |
| S-003 | 未確定入荷予定が全期間返る | 古い未確定も取得 | 日付で過剰に絞らない |
| S-004 | EOS確定済みは過去3日だけ返る | 検品日含む3日分のみ | 4日前以前を返さない |
| S-005 | 商品マスタ全件を含めない | `items` は互換用の空配列 | 入荷予定に必要な商品情報は `schedules[].item` に含まれる |
| S-006 | 実倉庫指定で仮想倉庫の未確定予定あり | `schedules` に仮想倉庫分も返る | `rules.matching_warehouse_ids` と `schedule.warehouse_id` |
| S-007 | 仮想倉庫指定 | 同一実倉庫配下の予定を返す | 作業倉庫はリクエスト倉庫、照合対象は実倉庫配下 |
| S-008 | EOS確定済みが仮想倉庫側にある | `confirmed_eos_index` に含まれる | 過去3日・同一実倉庫配下 |
